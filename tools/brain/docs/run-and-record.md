# Brain tools: run, record, smoke

How `brainrun.py run`, `record` and `smoke` work in detail. Back to the [runbook](../RUNBOOK.md) or the [index](../README.md).

## The one command: a full run with a report (spec #58, ticket #62)

`brainrun.py run` plays the top pick of every title on every side (KaijuFlow 1338, Usenet Ultimate 1339, AltMount's own addon 8086; with `--one-page` also "KaijuFlow, one page per indexer", which is the KaijuFlow config with pagination off), one side at a time, in four rounds: cold, warm, cold, warm. Each cold round first resets every test copy with `testbed.py` (and checks it is empty); warm rounds follow right after on the same state. It starts the indexer stand-in in **replay** mode itself (so every side sees the same recorded answers and no real indexer is contacted), reads KaijuFlow's `[KF-STEP]` lines and each Backend's import start/end from the test containers' own logs (`docker logs`, never `exec`), and stops the stand-in and all test copies at the end, also after an error. The one-page side comes after the three main sides; one shared step (`switch_to_one_page`, used by run, record and smoke alike) patches KaijuFlow's config while its copy is stopped, then resets KaijuFlow and its AltMount so they come up again cold; the config is restored at the end.

    python3 -I tools/brain/brainrun.py run --name baseline --store <standin-store> --list <title-list> [--one-page] [--titles-file titles.json] [--runs-root DIR]

**Stopping a run (#110).** Ctrl-C, or SIGTERM (what `timeout` sends when its time is up), stops the pass the way the cap rule does, and the normal ending follows: the config is restored, the stand-in and the test copies are stopped, and the run folder gets `raw.json`, `meta.json` and `report.md` from the plays that finished, plus an INDEX.md row with result `stopped` (see [formats](formats.md)). Right after the stop the run prints one line saying it is finishing its record; a second Ctrl-C or SIGTERM is ignored until the record is written. The command prints the check and exits with 130. A `kill -9` still loses the record. The report of a stopped run judges no target (the targets are judged on a finished run alone, in the report and in the check alike).

Run it in the background with a hard `timeout`, like the other tools; it prints one line per play, and each starts with the UTC time and how many plays are done out of those planned (`05:46:35 [61/160] kaijuflow cold 2 Inception: plays list 9.4 s start 6.1 s`), so `tail -1` of the log tells how far the run is. The lines of a reset start the same way (`05:46:10 [60/160] reset uu: up`), so no line between the run's first reset and its last play is without them. The record command's lines start the same way; its proof counts again from 1 and its lines say `proof` after the count. After each play the run pauses for `--settle` seconds (default 3). `--no-wait` starts the stand-in with its replay wait off (see below). `--user-id` defaults to the first manifest id of the first user in the test container's `config/users.json`; the AltMount download key is computed from `templates/altmount.key`. The recording is made earlier by `brainrun.py record` (next section) and spends real indexer requests.



`brainrun.py smoke --store <EMPTY folder> --list smoke` is the reachability check: stand-in in replay mode on an empty store (every request is a MISS, so nothing can be read from Usenet), one search per side, and it prints for each side how many stand-in requests it caused, which address they came from, the address `docker inspect` gives for the side's test container, and whether the two match (then one plain sentence says whether every side arrived with its own address). That is the check that the runner can tell the sides apart by address. It tries the same sides as the planned run: add `--one-page` when the run will use the fourth side; it is switched on with the same step as in a run (its address may equal KaijuFlow's, since it is the same container) and switched off at the end, which leaves KaijuFlow's copy stopped. Start the test copies with `testbed.py up` first and stop them with `testbed.py stop` afterwards.

Code: `brainreport.py` (log parsing, medians, failure split, diff, report, run folder and INDEX.md; pure logic), `brainrun.py` (orchestration), tests `test_brainreport.py` and `test_brainrun.py` (fakes and fixture logs, run in CI).

### Short runs (#111)

`run` takes `--sides kaijuflow,uu,altmount-addon,kaijuflow-1page` (any of them, comma-separated; the plan's order is kept; naming `kaijuflow-1page` alone plays the one-page side alone), `--rounds 1|2` (1 = cold 1 and warm 1; 2 = the full plan, the default) and `--quick` (= `--sides kaijuflow --rounds 1`, which does not imply `--no-wait`). `--quick` cannot be combined with `--sides` or `--rounds`, nor `--one-page` with `--sides`; an unknown side or other rounds stop before anything runs, and `record`, `smoke` and the others refuse the flags. Without them a run is as before.

A **short run** is any run that is not the full plan: the three main sides, 2 rounds and every title of the list (a `--titles-file` that leaves out titles of the built-in list counts, unless it is a tagged title list: a speed test's whole list, #167). `meta.json` keeps `sides`, `rounds`, `titles` and `short` (the words, for example `KaijuFlow, 1 round, 10 titles`; null for a full run). The report's first line says `Short run, not a baseline: <what was played>.`, the INDEX.md result column says `short: <what was played>`, `check` prints `Not usable as a baseline: short run (<what was played>)` and exits 1 (its other lines stay), and `build_page.py` refuses the folder. A short run is compared with the last run usable as a baseline (`check` exits 0), limited to the sides and titles it played; it is never itself the earlier run of another run.

## Record, top-up and misses (spec #72, ticket #75)

**The recipe, in order** (from the repo root; run the long ones in the background with a hard `timeout`):

1. Preflight: `python3 -I tools/brain/brainrun.py preflight --for record --store <store> --list <list>` (add `--rebuild-image` when it says the code that goes into the image has changed). Fix every sentence it prints.
2. Record: `python3 -I tools/brain/brainrun.py record --name <name> --store <store> --list <list> [--key-file PATH] [--one-page] [--titles-file titles.json]`. It runs the preflight itself, resets the test copies, starts the stand-in in **record** mode on the replay address, sends every side (KaijuFlow, Usenet Ultimate, AltMount's own addon, and with `--one-page` the fourth side) through every title in two rounds (#79): a cold round, then a warm round on the same state with no reset between (list, then play the top pick; sides one after another, order rotating per title). The warm round stores what only a warm visit asks for, such as KaijuFlow's health-check replacements for Sources that went dead in the cold round and the addon's second searches, so a run's warm list times are real numbers. The one-page side gets its own cold and warm round after the switch. Stops the stand-in and resets the test copies again. It ends with one sentence that also names any side that listed no Sources for some titles (a side whose copy did not answer shows up there), and last says how many top picks played per side and round, in `check`'s words ([formats.md](formats.md#recording-state-and-misses)). This spends real indexer requests and grabs.
3. Preflight for the run: `... preflight --for run --store <store> --list <list>`, then run: `python3 -I tools/brain/brainrun.py run --name <name> --store <store> --list <list> [--no-wait]` (it starts with the same preflight and refuses to start without a recording).

**Top-up.** Record mode serves a stored answer instead of asking the indexer again, so running `record` a second time (again both rounds) only asks for what is not stored yet (a second record of a complete list makes zero indexer requests). The report's "Not recorded" section prints the exact command.

**The proof and the record command's exit codes.** The record command ends with a proof: test copies reset, the stand-in in replay mode with the replay wait off (no indexer is contacted), every side through one cold and one warm round. Exit codes: 0 complete, 1 setup problem or failure, 2 stopped (limit reached), 3 incomplete (run the same command again), 130 stopped by Ctrl-C or SIGTERM. `brainrun.py --help` lists them.

**Stopping a record (#110).** Ctrl-C or SIGTERM anywhere in the record command, from its opening reset through the record pass to the proof, ends it the normal way: the stand-in is stopped, the config restored, the test copies reset and stopped, and, as for a run, one line says it is finishing its record and a second stop is ignored until it is written. What was stored is kept, `RECORDING.json` says `stopped` (so a run refuses the recording), the folder's `meta.json` has status `stopped`, INDEX.md gets a row with result `stopped`, and the exit code is 130. Run the same record command again: it only asks for what is not stored yet, then proves the recording.
