# Brain tools

Scripts for checks on Brain (the owner's server), first written for the 1338 Brain check (2026-11-09). The rules for every Brain check (the owner's go, live containers, indexers, connection caps) are in **[RUNBOOK.md](RUNBOOK.md)**, "Rules".

Run them with `python3 -I` from the repo root, wrapped in `timeout <seconds>`, in the shell tool's background mode. Each script prints one line per title as it goes and ends with `done in N s`; a log without that line is an unfinished run. Watch the log while it runs (a monitor that prints each title line and any line with `Error` or `Traceback`) and stop and report on the first error instead of waiting for the end.

`common.py` holds the ten titles, the timed HTTP read and a Stream play; change the title list there only. `--titles-file <path.json>` (a JSON list of `[kind, id, label]`) swaps in another list for one run, e.g. fresh titles for a cold run. The user id is the id in KaijuFlow's manifest URL, the key in the test container's `config/users.json`.

| Script | What it does | Cost |
|---|---|---|
| `backup.sh` | Copies the recording store `~/kaijuflow-test/store` into `~/kaijuflow-notes/recordings/`, then commits and pushes `~/kaijuflow-notes` to the private repo `ReyesPascal/kaijuflow-notes` (#114). Runbook step 7. | Pushes to GitHub; no indexer, Usenet or container is touched |
| `indexer_standin.py --mode record\|replay --config <indexers.json> --store <dir> --list <name>` | Indexer stand-in on port 1340 (#59). A side points its indexer URL at `http://<host>:1340/<indexer-slug>/api` with any dummy key. Record mode passes search and NZB requests to the real indexer (keys live only in the config outside the repo) and stores each answer per title list; NZB links in search answers (XML, and JSON with escaped `\/` or plain slashes) are rewritten to lead back to the stand-in, and no occurrence of the real key (plain, URL-encoded or JSON-escaped) is stored or sent to a side in any body; `/nzb/<token>` only resolves to the configured indexer's own host (anything else is a 403 `REFUSED`, nothing is sent). Replay serves the stored answers byte-identical and never contacts the indexer; a miss is a 503 `not recorded` (a refusal, so a gap in a Recording never makes KaijuFlow mark a Source dead, ADR 0004) and a `MISS` log line. A "limit reached" answer (XML `<error>` or newznab JSON `{"error":{"@attributes":{...}}}`, or HTTP 429) while recording writes `<store>/LIMIT_REACHED.json`, logs `LIMIT_REACHED`, is not stored, and the process exits with status 3. **Indexer time and dropped parameters (#73):** each stored answer keeps the milliseconds the real indexer took; replay waits that long before answering (search answers and NZB files) unless started with `--no-wait`, and every served stored answer logs `HIT <slug> <request> wait_ms=<n> from=<client address> t=<epoch ms>` (0 when the wait is off or the recording has no time; older recordings still replay). **Who asked, and when:** every request line (`HIT`, `MISS`, `RECORD`, and `ERROR`) ends with `from=<client address> t=<epoch ms the answer was sent>`, so the runner can tell which side's container asked. **What is stored (record mode):** only HTTP 2xx answers that are not a newznab error, plus 404 and 410 (an NZB that is gone stays gone). Every other answer (5xx, network error, other 4xx, a newznab error that is not a limit) is passed on to the side, not stored, and logged as `ERROR <slug> <request> -> <status>`; a top-up asks again. Two identical requests arriving together reach the real indexer once (the second waits and gets the stored answer). An indexer entry in the key file may carry `"drop_params": ["o"]`: those request parameters are removed before the request is looked up or forwarded, as the live DrunkenSlug proxy (`ds-xml-proxy`, which strips `o=json` because AltMount 0.4.0 cannot read DrunkenSlug's JSON) does; the list is saved in the recording as `<store>/<list>/<slug>/indexer.json` (no key in it), so replay needs no key file. The setting is fixed once a list holds answers for that indexer: a record whose key file gives a different setting for it (including none) stops with one sentence (use a new list name) instead of changing it. KaijuFlow asks for XML, so dropping the output-format parameter changes nothing for it. Test: `test_indexer_standin.py` (CI runs it). | Record mode spends real indexer requests and grabs; replay spends none |
| `pool.py draw --test <speed test> --out <titles.json>`, `pool.py check-ids` | The pool of titles speed tests draw from (`pool.json`, #165). `draw` takes 6 unused films and 4 unused episodes from each list (easy, hard), writes the speed test's tagged title list (`[type, id, label, list]`) and marks them used; it refuses a pool that is too small or holds one of Test 1's ten titles, with one sentence and nothing marked. `check-ids` checks every ID, and an episode's season and episode, against TMDB with the metadata key it reads from KaijuFlow's test copy and never prints. Format and how to fill it: [docs/formats.md](docs/formats.md#the-pool-pooljson-and-the-tagged-title-list). Test: `test_pool.py`, on TMDB answers captured on 2026-11-15 (`fixtures/2026-11-15-tmdb/`). | `draw`: none, it only changes the pool file. `check-ids`: two TMDB requests per episode, one per film; no indexer, Usenet or container is touched |
| `draw.py titles --check <name> --kinds <kind>=<n>,... --out <titles.json>`, `draw.py seed` | The title draw for real-use checks (#269, ADR 0010): new titles from TMDB by kind (popular or rare, film or episode, foreign, anime, remake, daily), none in the ledger of titles already played (`~/kaijuflow-notes/brain-runs/titles-played.json`), each ID checked as `pool.py check-ids` does; writes the ledger, then the check's title list (`[type, id, label, kind, date]`). `--kinds anime=1` is a replacement. `seed` adds the old speed tests' titles to the ledger. Format: [docs/formats.md](docs/formats.md#the-title-draw-and-the-ledger-drawpy). Test: `test_draw.py`, on a fake TMDB and on TMDB answers captured on 2026-11-24 (`fixtures/2026-11-24-tmdb-draw/`). | TMDB only, a few requests per title; no indexer, Usenet or container is touched |
| `frontier.py [parent]` | The tickets that can start now (#126): the open sub-issues of the parent (default #183, the map) with no open blocker and no assignee, in the parent's sub-issue order, one line each with all its labels (for example `[bug, ready-for-agent]`) and the title; one line saying so when none qualifies. The repo is the clone's own (`gh` fills `{owner}/{repo}`). Exits 0; 1 when `gh` fails or prints no JSON; 2 when the parent is not a number (one line on stderr). The `/kf` skill and the handoff note's "The tracker" section point at it. Test: `test_frontier.py`, on a captured `gh api` answer (`fixtures/2026-11-14/`). | One read-only `gh api` call; no indexer, Usenet or container is touched |
| `prwatch.py <pr> [--interval S] [--timeout S]` | Whether a PR is ready to merge (#231): one line at once (checks, how many still running, head commit), then one line on the first final state: `PR #n GREEN at <sha>` (exit 0), `RED at <sha>: <failed checks>` (1), a gh error (2) or `TIMEOUT` (3, default 1800 s). A new push restarts the wait. Run it in the background after every push (`docs/agents/issue-tracker.md`, "Watch every PR you push"). Reads `gh pr view --json statusCheckRollup` (gh 2.46 has no `gh pr checks --json`). Test: `test_prwatch.py`, on PR #230's captured answer (`fixtures/2026-11-23-prwatch/`). | One read-only `gh` call per poll |
| `unreported.py [runs root]` | The runs the handoff note may not know (#229): the `INDEX.md` rows dated after the last commit of `~/kaijuflow-notes/NEXT_SESSION.md`, one line each (date, name, result, folder), or `none`. `docs/agents/resume.md` step 3 runs it. Exits 0; 1 when git cannot date the note. Test: `test_unreported.py`. | Reads `INDEX.md` and git only |
| `casebook.py index`, `casebook.py check` | The Casebook (#281, spec #279): one Markdown file per known cause of a play going wrong in `casebook/`, and its index `casebook/index.json`. `index` rewrites the index from the entry files (never edit it by hand); `check` lists every entry that breaks the format, every disagreement between the index and the files, and every entry that claims proved (`proved fixed`, `reopened`) without a confirming test that runs (a `confirm` recipe whose Clues are all in the Clue library, `clues.py`); exit 1 when there is one. Format: [casebook/README.md](casebook/README.md). Test: `test_casebook.py`, which also checks the repo's own Casebook. | Reads the repo only |
| `diagnosis.py diagnose <check folder \| evidence folder>`, `diagnosis.py record <check folder>`, `diagnosis.py refingerprint [runs root]` | Diagnosis (#283, spec #279): for every failure of every failed or fallen-back play (one per Source AltMount refused, or one for the play), one line: *found: X, proved by Clues A, B*, *suspected: X (no confirming test)* or *new*. It fingerprints the failure (`masking-rules.json`), takes the Casebook entries whose signs fit as leads, and runs each lead's confirming recipe of Clues (`clues.py`) on the play's own evidence folder: only a passing recipe names a cause, a failing one rules the lead out. `diagnose` writes each folder's `diagnosis.json` and the check's summary; a quick check runs it by itself at its end when a play left an evidence folder, and its report gets a Diagnosis section. `record` puts a diagnosed check's proved occurrences and ruled-out leads on the Casebook entries and writes the index again (commit them; the check itself leaves the repo clean). `refingerprint` fingerprints every stored failure under the runs root again after the masking rules' version changes (a check does it first, too). Formats: [docs/formats.md](docs/formats.md#diagnosis). Test: `test_diagnosis.py`, on four real plays cut into evidence folders (`fixtures/2026-11-24-diagnosis/`). | Reads the evidence folders and the repo; `record` changes the Casebook's files |
| `statcheck.py <file.nzb>` | NNTP `STAT` for every article; reports missing ones per file (video parts vs par2). | No downloads; about 9 min for 50k articles on 8 connections |
| `rarorder.py <file.nzb>` | Real RAR volume number of each scrambled, number-named part (first article of each part). | One article per part |

`nntp.py` holds the shared provider login, read from the test copy's AltMount `config.yaml` (`altmount-kf/config/` in the test folder, `TEST_DIR` or `common.DEFAULT_TEST_DIR`; #284), and `Usenet`, the one read-only connection the live Clues use.

**Which tools touch the live services.** `brainrun.py check --quick` (the quick check, #270) asks the live indexer through the stand-in in record mode (up to 60 searches and 150 downloads; its preflight refuses a check the allowance cannot hold) and TMDB for the draw; otherwise `brainrun.py` only uses the test copies (`parity.py`, the side-by-side byte check against UU, was deleted in #187). `statcheck.py` and `rarorder.py` read Usenet, and so does a quick check with a failure at its end: its live read-only Clues (#284) ask the test copy's provider about each failed Source's kept NZB over one connection (STAT, and BODY checked in memory; nothing saved but their answers). `indexer_standin.py` in record mode spends real indexer requests. Everything else here (`testbed.py`, `brainrun.py preflight|run|smoke`) touches the test copies only, `frontier.py` reads only the tracker, and `pool.py check-ids` only TMDB. DrunkenSlug note: live AltMount reaches DrunkenSlug through `ds-xml-proxy` (port 8099), which removes `o=json` because AltMount 0.4.0 cannot read DrunkenSlug's JSON; the stand-in does the same through `drop_params` in the key file.

## Index

Start with **[RUNBOOK.md](RUNBOOK.md)**: the one-page recipe for a timed run (preflight, record, run, check). The reference pages hold the rest:

- [docs/run-and-record.md](docs/run-and-record.md): how `brainrun.py run`, `record`, `smoke` and the record recipe work, the short-run flags of `run` (`--sides`, `--rounds`, `--quick`; a short run is never a baseline), and the record command's exit codes.
- [docs/rules.md](docs/rules.md): how a real-use check (`brainrun.py check --quick`) is judged, what a run is (one setup, untouched answers, one try per title until #190 turned fallback on, the Play-time check; #185) and how it is judged against the previous run, the cap rule, the settings table and preflight, the expected settings the preflight holds the test copies to, the replay wait, the indexer allowance (`limits.json`, `usage`), how the targets are judged.
- [docs/formats.md](docs/formats.md): run folder, top picks, the Speed Check page's targets file (`targets.json`), the expected settings file (`expected-settings.json`), the pool (`pool.json`) and the tagged title list, recording state, misses, the evidence folder, Diagnosis (fingerprints, the masking file, the Clue format, `diagnosis.json`), the page's `findings.html`, and the `[KF-STEP]` step lines.
- [docs/testbed.md](docs/testbed.md): the test copies of the one setup (`compose.test.yaml`, `testbed.py`) and the 1338 test container.

Code: `brainreport.py` (log parsing, medians, report, run folder; pure logic), `brainrun.py` (orchestration), `allowance.py`, `runcheck.py` (`check`, and the judgement against the previous run), `testbed.py`, `build_page.py`, `startline.py` and `pagetargets.py` (the Speed Check page and its one-page Letter report from run folders, in the Starting line design, and its targets held against other setups; page code until #195; RUNBOOK, "Publish the page"), `frontier.py` (the tickets that can start now, from the tracker), `prwatch.py` (whether a PR is ready to merge), `unreported.py` (runs newer than the handoff note), `pool.py` (the pool and the draw), `draw.py` (the title draw for real-use checks and its ledger), `quickcheck.py` (the quick check's judging: the right-title match, each play's outcome, the verdict and report.md; `brainrun.py check --quick` runs it), `evidence.py` (the evidence folder of a failed or fallen-back play, one shared part for every check; formats, "Evidence folder"); `casebook.py` (the Casebook's format check and its generated index), `clues.py` (the Clue library the Casebook's confirming tests are recipes of) and `diagnosis.py` (Diagnosis: fingerprints, leads, proof, the check's Diagnosis section; `masking-rules.json` its masking rules); `render.mjs` (screenshots a page and flags layout faults before publishing; RUNBOOK, "Publish the page"); tests are the `test_*.py` files next to them; `npm run check:brain` runs them with compile and lint, as CI does (no Docker).
