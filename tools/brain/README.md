# Brain tools

Scripts for checks on Brain (the owner's server), first written for the 1338 Brain check (2026-11-09). The rules for every Brain check (the owner's go, live containers, indexers, connection caps) are in **[RUNBOOK.md](RUNBOOK.md)**, "Rules".

Run them with `python3 -I` from the repo root, wrapped in `timeout <seconds>`, in the shell tool's background mode. Each script prints one line per title as it goes and ends with `done in N s`; a log without that line is an unfinished run. Watch the log while it runs (a monitor that prints each title line and any line with `Error` or `Traceback`) and stop and report on the first error instead of waiting for the end.

`common.py` holds the ten titles, the timed HTTP read and the table helpers shared by `parity.py` and `search.py`; change the title list there only, so both tables stay comparable. `TITLES_FILE=<path.json>` (a JSON list of `[kind, id, label]`) swaps in another list for one run, e.g. fresh titles for a cold run. `<user-id>` is the id in UU's manifest URL, the key in the test container's `config/users.json`. AltMount's download key (the SHA-256 of its API key) is computed in `src/backends/altmount.ts` (`downloadKey`).

|---|---|---|
| `backup.sh` | Copies the recording store `~/kaijuflow-test/store` into `~/kaijuflow-notes/recordings/`, then commits and pushes `~/kaijuflow-notes` to the private repo `ReyesPascal/kaijuflow-notes` (#114). | `parity.py <user-id> <out.json>` | Plays the first Source of 10 titles through UU 1337 (NzbDAV) and the test container on 1338. It reads 64 KiB at the start, 50% and 90%, notes the failure video, and compares bytes between the two sides. It records each side's speed (#46): time to the Stream being ready (response headers), time to the first byte, the start read, the 50% and 90% seek reads, and the test container's Unscramble time from `docker logs`; it prints a Markdown table with the median per side and writes it to `<out>.md`. `<user-id>` is the id in the manifest URL; `PARITY_TITLES="Interstellar,Game of Thrones"` reruns only those titles. | Plays real Streams through the live services; superseded by `brainrun.py`. Starts real Streams on both Backends |
| `search.py <user-id> <download-key> <out.json>` | Search side-by-side: the same 10 titles through AltMount's own Stremio addon on 8085, the test container on 1338 and UU 1337. Per title and side it records the Sources shown, the time until the list arrived, whether the first Stream plays on the first try, the time to the first byte of the first Stream that plays, and how many of the first 3 Streams are broken (error or failure video); medians per side as a Markdown table in `<out>.md`. Sides run one after the other, order rotating per title. `<download-key>` is the lowercase hex SHA-256 of AltMount's API key (its addon URL is `/stremio/<download-key>/manifest.json`). `SEARCH_TITLES`, `SEARCH_TRIES` and `SEARCH_SIDES` narrow a run. | Plays real Streams through the live services; superseded by `brainrun.py`. Starts real Streams on all three sides; the addon plays import NZBs into AltMount's library (categories Movies/TV) |
| `indexer_standin.py --mode record\|replay --config <indexers.json> --store <dir> --list <name>` | Indexer stand-in on port 1340 (#59). A side points its indexer URL at `http://<host>:1340/<indexer-slug>/api` with any dummy key. Record mode passes search and NZB requests to the real indexer (keys live only in the config outside the repo) and stores each answer per title list; NZB links in search answers (XML, and JSON with escaped `\/` or plain slashes) are rewritten to lead back to the stand-in, and no occurrence of the real key (plain, URL-encoded or JSON-escaped) is stored or sent to a side in any body; `/nzb/<token>` only resolves to the configured indexer's own host (anything else is a 403 `REFUSED`, nothing is sent). Replay serves the stored answers byte-identical and never contacts the indexer; a miss is a 404 and a `MISS` log line. A "limit reached" answer (XML `<error>` or newznab JSON `{"error":{"@attributes":{...}}}`, or HTTP 429) while recording writes `<store>/LIMIT_REACHED.json`, logs `LIMIT_REACHED`, is not stored, and the process exits with status 3. **Indexer time and dropped parameters (#73):** each stored answer keeps the milliseconds the real indexer took; replay waits that long before answering (search answers and NZB files) unless started with `--no-wait`, and every served stored answer logs `HIT <slug> <request> wait_ms=<n> from=<client address> t=<epoch ms>` (0 when the wait is off or the recording has no time; older recordings still replay). **Who asked, and when:** every request line (`HIT`, `MISS`, `RECORD`, and `ERROR`) ends with `from=<client address> t=<epoch ms the answer was sent>`, so the runner can tell which side's container asked. **What is stored (record mode):** only HTTP 2xx answers that are not a newznab error, plus 404 and 410 (an NZB that is gone stays gone). Every other answer (5xx, network error, other 4xx, a newznab error that is not a limit) is passed on to the side, not stored, and logged as `ERROR <slug> <request> -> <status>`; a top-up asks again. Two identical requests arriving together reach the real indexer once (the second waits and gets the stored answer). An indexer entry in the key file may carry `"drop_params": ["o"]`: those request parameters are removed before the request is looked up or forwarded, as the live DrunkenSlug proxy (`ds-xml-proxy`, which strips `o=json` because AltMount 0.4.0 cannot read DrunkenSlug's JSON) does; the list is saved in the recording as `<store>/<list>/<slug>/indexer.json` (no key in it), so replay needs no key file. The setting is fixed once a list holds answers for that indexer: a record whose key file gives a different setting for it (including none) stops with one sentence (use a new list name) instead of changing it. Only AltMount sends the output-format parameter (KaijuFlow and Usenet Ultimate ask for XML), so dropping it changes nothing for the other sides. Test: `test_indexer_standin.py` (CI runs it). | Record mode spends real indexer requests and grabs; replay spends none |
| `frontier.py [parent]` | The tickets that can start now (#126): the open sub-issues of the parent (default #58, the map) with no open blocker and no assignee, in the parent's sub-issue order, one line each with all its labels (for example `[bug, ready-for-agent]`) and the title; one line saying so when none qualifies. The repo is the clone's own (`gh` fills `{owner}/{repo}`). Exits 0; 1 when `gh` fails or prints no JSON; 2 when the parent is not a number (one line on stderr). The `/kf` skill and the handoff note's "The tracker" section point at it. Test: `test_frontier.py`, on a captured `gh api` answer (`fixtures/2026-11-14/`). | One read-only `gh api` call; no indexer, Usenet or container is touched |
| `statcheck.py <file.nzb>` | NNTP `STAT` for every article; reports missing ones per file (video parts vs par2). | No downloads; about 9 min for 50k articles on 8 connections |
| `rarorder.py <file.nzb>` | Real RAR volume number of each scrambled, number-named part (first article of each part). | One article per part |

`nntp.py` holds the shared provider login, read from AltMount's `config.yaml` (`~/altmount-stack/config/`).

**Which tools touch the live services.** `parity.py` and `search.py` play real Streams through the live services (UU 1337, AltMount 8085) and are superseded by `brainrun.py`, which only uses the test copies. `statcheck.py` and `rarorder.py` read Usenet. `indexer_standin.py` in record mode spends real indexer requests. Everything else here (`testbed.py`, `brainrun.py preflight|run|smoke`) touches the test copies only, and `frontier.py` reads only the tracker. DrunkenSlug note: live AltMount reaches DrunkenSlug through `ds-xml-proxy` (port 8099), which removes `o=json` because AltMount 0.4.0 cannot read DrunkenSlug's JSON; the stand-in does the same through `drop_params` in the key file.

## Index

Start with **[RUNBOOK.md](RUNBOOK.md)**: the one-page recipe for a timed run (preflight, record, run, check). The reference pages hold the rest:

- [docs/run-and-record.md](docs/run-and-record.md): how `brainrun.py run`, `record`, `smoke` and the record recipe work, the short-run flags of `run` (`--sides`, `--rounds`, `--quick`; a short run is never a baseline), and the record command's exit codes.
- [docs/rules.md](docs/rules.md): the cap rule, the settings table and preflight, the expected settings the preflight holds the test copies to, the replay wait, the indexer allowance (`limits.json`, `usage`), how the targets are judged.
- [docs/formats.md](docs/formats.md): run folder, top picks, the targets file (`targets.json`), the expected settings file (`expected-settings.json`), recording state, misses, the page's `findings.html`, and the `[KF-STEP]` step lines.
- [docs/testbed.md](docs/testbed.md): the test copies of every side (`compose.test.yaml`, `testbed.py`) and the 1338 test container.

Code: `brainreport.py` (log parsing, medians, targets, report, run folder; pure logic), `brainrun.py` (orchestration), `allowance.py`, `runcheck.py`, `testbed.py`, `build_page.py` and `startline.py` (the Speed Check page and its one-page Letter report from run folders, in the Starting line design; RUNBOOK, "Publish the page"), `frontier.py` (the tickets that can start now, from the tracker); `render.mjs` (screenshots a page and flags layout faults before publishing; RUNBOOK, "Publish the page"); tests are the `test_*.py` files next to them; `npm run check:brain` runs them with compile and lint, as CI does (no Docker).
