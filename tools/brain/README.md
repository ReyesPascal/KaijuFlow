# Brain tools

Scripts for checks on Brain (the owner's server), first written for the 1338 Brain check (2026-11-09). Every rule (the owner's go, the test copies, indexers, connection caps, and the rest) is in **[docs/rules.md](docs/rules.md)**, its one home; the steps are in **[RUNBOOK.md](RUNBOOK.md)**.

Run them with `python3 -I` from the repo root, as [Long commands and their logs](docs/rules.md#long-commands-and-their-logs) says: a check's log ends with the exit code the runbook's command line appends, and is watched through the runbook's one filter.

`common.py` holds the timed HTTP read and a Stream play; a check's titles are drawn new each time by `draw.py` (ADR 0010).

| Script | What it does | Cost |
|---|---|---|
| `backup.sh` | Commits and pushes `~/kaijuflow-notes` (the check folders and the ledger) to the private repo `ReyesPascal/kaijuflow-notes` (#114). Refuses to push if a value from a key file in `~/kaijuflow-test` appears in the check folders. Needs no recording store and touches no recording (#312). `KF_NOTES` overrides the notes folder. Runbook, "Before a check" step 3. | Pushes to GitHub; no indexer, Usenet or container is touched |
| `indexer_standin.py --mode record --config <indexers.json> --store <dir> --list <name>` | Indexer stand-in on port 1340 (#59). A side points its indexer URL at `http://<host>:1340/<indexer-slug>/api` with any dummy key. A real-use check starts it in record mode on the check's own empty store: it passes search and NZB requests to the real indexer (keys live only in the config outside the repo) and stores each answer, so a failed play's evidence folder keeps them; NZB links in search answers (XML, and JSON with escaped `\/` or plain slashes) are rewritten to lead back to the stand-in, and no occurrence of the real key (plain, URL-encoded or JSON-escaped) is stored or sent to a side in any body; `/nzb/<token>` only resolves to the configured indexer's own host (anything else is a 403 `REFUSED`, nothing is sent). A "limit reached" answer (XML `<error>` or newznab JSON `{"error":{"@attributes":{...}}}`, or HTTP 429) writes `<store>/LIMIT_REACHED.json`, logs `LIMIT_REACHED`, is not stored, and the process exits with status 3: the cap rule reads it. Every request line (`RECORD`, `ERROR`, `HIT`, `MISS`) ends with `from=<client address> t=<epoch ms the answer was sent>`; the `RECORD` and `ERROR` lines are what the allowance counts. Only HTTP 2xx answers that are not a newznab error, plus 404 and 410, are stored; every other answer is passed on to the side, not stored, and logged as `ERROR <slug> <request> -> <status>`. Two identical requests arriving together reach the real indexer once. An indexer entry in the key file may carry `"drop_params": ["o"]`: those request parameters are removed before the request is forwarded, as the live DrunkenSlug proxy (`ds-xml-proxy`, which strips `o=json` because AltMount 0.4.0 cannot read DrunkenSlug's JSON) does. Its replay mode served a stored Recording to the retired timed runs (ADR 0010; [archive/README.md](archive/README.md)). Test: `test_indexer_standin.py` (CI runs it). | Record mode spends real indexer requests and grabs |
| `pool.py` | The TMDB lookups the title draw, the quick check and the Drill-down share: `tmdb_getter` (the metadata key of KaijuFlow's test copy, read there and never printed) and `check_title` (a title's ID, season and episode against TMDB). The speed tests' pool and its commands are retired by ADR 0010 and archived (`archive/pool_draw.py`, `archive/pool.json`). | TMDB only, when a caller asks |
| `draw.py titles --check <name> --kinds <kind>=<n>,... --out <titles.json>`, `draw.py seed` | The title draw for real-use checks (#269, ADR 0010): new titles from TMDB by kind (popular or rare, film or episode, foreign, anime, remake, daily), none in the ledger of titles already played (`~/kaijuflow-notes/brain-runs/titles-played.json`), each ID checked against TMDB (`pool.check_title`); writes the ledger, then the check's title list (`[type, id, label, kind, date]`). `--kinds anime=1` is a replacement. `seed` adds the old speed tests' titles (`archive/pool.json`) to the ledger. Format: [docs/formats.md](docs/formats.md#the-title-draw-and-the-ledger-drawpy). Test: `test_draw.py`, on a fake TMDB and on TMDB answers captured on 2026-11-24 (`fixtures/2026-11-24-tmdb-draw/`). | TMDB only, a few requests per title; no indexer, Usenet or container is touched |
| `frontier.py [parent]` | The tickets that can start now (#126): the open sub-issues of the parent (default #183, the map) with no open blocker and no assignee, in the parent's sub-issue order, one line each with all its labels (for example `[bug, ready-for-agent]`) and the title; one line saying so when none qualifies. The repo is the clone's own (`gh` fills `{owner}/{repo}`). Exits 0; 1 when `gh` fails or prints no JSON; 2 when the parent is not a number (one line on stderr). The `/kf` skill and the handoff note's "The tracker" section point at it. Test: `test_frontier.py`, on a captured `gh api` answer (`fixtures/2026-11-14/`). | One read-only `gh api` call; no indexer, Usenet or container is touched |
| `prwatch.py <pr> [--interval S] [--timeout S]` | Whether a PR is ready to merge (#231): one line at once (checks, how many still running, head commit), then one line on the first final state: `PR #n GREEN at <sha>` (exit 0), `RED at <sha>: <failed checks>` (1), a gh error (2) or `TIMEOUT` (3, default 1800 s). A new push restarts the wait. Run it in the background after every push (`docs/agents/issue-tracker.md`, "Watch every PR you push"). Reads `gh pr view --json statusCheckRollup` (gh 2.46 has no `gh pr checks --json`). Test: `test_prwatch.py`, on PR #230's captured answer (`fixtures/2026-11-23-prwatch/`). | One read-only `gh` call per poll |
| `unreported.py [runs root]` | The runs the handoff note may not know (#229): the `INDEX.md` rows dated after the last commit of `~/kaijuflow-notes/NEXT_SESSION.md`, one line each (date, name, result, folder), or `none`. `docs/agents/resume.md` step 3 runs it. Exits 0; 1 when git cannot date the note. Test: `test_unreported.py`. | Reads `INDEX.md` and git only |
| `casebook.py index`, `casebook.py check` | The Casebook (#281, spec #279): one Markdown file per known cause of a play going wrong in `casebook/`, and its index `casebook/index.json`. `index` rewrites the index from the entry files (never edit it by hand); `check` lists every entry that breaks the format, every disagreement between the index and the files, and every entry that claims proved (`proved fixed`, `reopened`) without a confirming test that runs (a `confirm` recipe whose Clues are all in the Clue library, `clues.py`); exit 1 when there is one. Format: [casebook/README.md](casebook/README.md). Test: `test_casebook.py`, which also checks the repo's own Casebook. | Reads the repo only |
| `diagnosis.py diagnose <check folder \| evidence folder>`, `diagnosis.py record <check folder>`, `diagnosis.py refingerprint [runs root]`, `diagnosis.py fix <check folder> [--casebook DIR] [--dry-run]` | Diagnosis (#283, spec #279): for every failure of every failed or fallen-back play (one per Source AltMount refused, or one for the play), one line: *found: X, proved by Clues A, B*, *suspected: X (no confirming test)* or *new*. It fingerprints the failure (`masking-rules.json`), takes the Casebook entries whose signs fit as leads, and runs each lead's confirming recipe of Clues (`clues.py`) on the play's own evidence folder: only a passing recipe names a cause, a failing one rules the lead out. `diagnose` writes each folder's `diagnosis.json` and the check's summary; a quick check runs it by itself at its end when a play left an evidence folder, and its report gets a Diagnosis section. `record` puts a diagnosed check's proved occurrences and ruled-out leads on the Casebook entries and writes the index again (commit them; the check itself leaves the repo clean). `refingerprint` fingerprints every stored failure under the runs root again after the masking rules' version changes (a check does it first, too). After a check, a proved KaijuFlow cause files its own fix ticket (`ready-for-agent`, under the map, with its proof and the Drill-down command; its text in `fix-tickets/`, filed unless `brainrun.py check --quick --tickets-dry-run`), a cause that is not KaijuFlow's gets its workaround and no ticket, and a failure that proves a `proved fixed` cause is a comeback that `record` reopens; `fix` does the same for a check diagnosed again with a new entry ([Fixing](docs/formats.md#fixing), #288); the report's Diagnosis section ends with the scoreboard (Clues reused against new, fixes proved and comebacks, failures per check by cause, research). Formats: [docs/formats.md](docs/formats.md#diagnosis). Test: `test_diagnosis.py`, on four real plays cut into evidence folders (`fixtures/2026-11-24-diagnosis/`); `test_fixing.py`, `test_scoreboard.py`. | Reads the evidence folders and the repo; a check files fix tickets (gh); `record` changes the Casebook's files |
| `brainrun.py drill --title <imdb id> [--episode S01E02] [--entry ID ...]` | The Drill-down (#272, spec #279; `drill.py`): one failed title played again live through the quick check's own path (preflight for one title, reset, stand-in live, one press of Best, the same verdict and report), not drawn and not added to the ledger. Its play always keeps an evidence folder; after Diagnosis, the suspected causes (the entries proved on the title's earlier evidence folders, and every `--entry`) get their confirming recipe run on the drill's failures and are marked proved fixed, reopened or not marked (`diagnosis.json` `drill`, the report's Drill-down section); `diagnosis.py record <drill folder>` writes the marks on the entries. Format: [docs/formats.md](docs/formats.md#drill-down). Test: `test_drill.py`, on the captured Witcher play. | As a quick check of one title: up to 12 searches and 30 downloads of the live indexer, TMDB when no earlier folder names the title, the live Clues when a failed Source kept its NZB |
| `diagnosis.py case list\|show\|run\|add\|repeat\|entry ...` | Case logs (#287, spec #279): a failure Diagnosis could not prove opens a Case log in the notes repo (`~/kaijuflow-notes/diagnosis/cases/<id>/`, `case.json` and a readable `CASE.md`), or joins the one with its fingerprint, with the code's first attempt (the path to the first wrong step, what changed since the last check that passed, the leads, every Clue run once). The check then starts the diagnosing agent by itself (herdr's `agents` tab, else `claude -p`) and tells the owner in one line (`kf-alert`). The agent works the log only through these commands, with the routine in [docs/diagnosing-agent.md](docs/diagnosing-agent.md): `run` never runs a Clue twice on an occurrence; `add` refuses a claim whose quote the evidence does not hold; `repeat` adds a Drill-down's or replay's folder (probable becomes proved); `entry` writes a concluded log up as a Casebook entry. Formats: [docs/formats.md](docs/formats.md#case-log). Test: `test_caselog.py`. | Reads the evidence folders; writes the Case logs; `entry` writes a Casebook entry and the index; a check's start of the agent opens a herdr pane or a `claude -p` |
| `statcheck.py <file.nzb>` | NNTP `STAT` for every article; reports missing ones per file (video parts vs par2). | No downloads; about 9 min for 50k articles on 8 connections |
| `rarorder.py <file.nzb>` | Real RAR volume number of each scrambled, number-named part (first article of each part). | One article per part |

`nntp.py` holds the shared provider login, read from the test copy's AltMount `config.yaml` (`altmount-kf/config/` in the test folder, `TEST_DIR` or `common.DEFAULT_TEST_DIR`; #284), and `Usenet`, the one read-only connection the live Clues use.

**Which tools touch the live services.** `brainrun.py check --quick` (the quick check, #270), and `brainrun.py drill` (one title, #272), ask the live indexer through the stand-in in record mode (up to 60 searches and 150 downloads, a drill 12 and 30, plus the preflight's one caps request per indexer, #303; the preflight refuses a check the allowance cannot hold) and TMDB for the draw (a drill only for a title no earlier evidence folder names); otherwise `brainrun.py` only uses the test copies (`parity.py`, the side-by-side byte check against UU, was deleted in #187). `statcheck.py` and `rarorder.py` read Usenet, and so does a quick check with a failure at its end: its live read-only Clues (#284) ask the test copy's provider about each failed Source's kept NZB over one connection (STAT, and BODY checked in memory; nothing saved but their answers). `indexer_standin.py` in record mode spends real indexer requests. Everything else here (`testbed.py`, `brainrun.py preflight|usage`, `checkpage.py`) touches the test copies or the check folders only, and `frontier.py` reads only the tracker. DrunkenSlug note: live AltMount reaches DrunkenSlug through `ds-xml-proxy` (port 8099), which removes `o=json` because AltMount 0.4.0 cannot read DrunkenSlug's JSON; the stand-in does the same through `drop_params` in the key file.

## Index

Start with **[RUNBOOK.md](RUNBOOK.md)**: the one-page recipe for a real-use check (preflight, the quick check, the drill-down, back up, the page). The reference pages hold the rest:

- [docs/rules.md](docs/rules.md): every rule, each one sentence with why and what enforces it (machine and power, indexers and allowance, the preflight, test copies and settings, checks and verdicts, building and reviewing, the tracker, secrets, sessions).
- [docs/formats.md](docs/formats.md): the expected settings file (`expected-settings.json`), the title draw and its ledger, the check folder, the Speed Check page (`checkpage.py`), the evidence folder, Diagnosis (fingerprints, the masking file, the Clue format, `diagnosis.json`), Fixing, the Drill-down, Case logs, and the `[KF-STEP]` step lines.
- [docs/testbed.md](docs/testbed.md): the test copies of the one setup (`compose.test.yaml`, `testbed.py`), the indexer command, the key file's limits and `usage`, and the 1338 test container.
- [archive/README.md](archive/README.md): the replayed Recording and its process, retired by ADR 0010 and archived, not deleted (`retired.py` stops its commands unless `--revive`).

Code: `brainreport.py` (log parsing, the step lines, shared helpers; pure logic), `brainrun.py` (the checks' orchestration and preflight), `allowance.py`, `testbed.py`, `checkpage.py` (the Speed Check page of real-use checks; RUNBOOK, "Publish the page"), `retired.py` (the retired commands' gate and the live docs' check, `test_live_docs.py`), `frontier.py` (the tickets that can start now, from the tracker), `prwatch.py` (whether a PR is ready to merge), `unreported.py` (checks newer than the handoff note), `pool.py` (the TMDB lookups), `draw.py` (the title draw for real-use checks and its ledger), `quickcheck.py` (the quick check's judging: the right-title match, each play's outcome, the verdict and report.md; `brainrun.py check --quick` runs it), `evidence.py` (the evidence folder of a failed or fallen-back play, one shared part for every check; formats, "Evidence folder"); `casebook.py` (the Casebook's format check and its generated index), `clues.py` (the Clue library the Casebook's confirming tests are recipes of) `diagnosis.py` (Diagnosis: fingerprints, leads, proof, the check's Diagnosis section; `masking-rules.json` its masking rules), `fixing.py` (a proved cause's fix ticket, workaround or comeback), `scoreboard.py` (the Diagnosis section's four extra numbers) and `caselog.py` (Case logs, the claim check and the diagnosing agent's start); `render.mjs` (screenshots a page and flags layout faults before publishing; RUNBOOK, "Publish the page"); tests are the `test_*.py` files next to them; `npm run check:brain` runs them with compile and lint, as CI does (no Docker).
