## App shell coupling to cut deliberately

The strongest evidence of extraction cost is [PlayerViewModel constructor/imports](https://github.com/ReyesPascal/Pascal-The-Popcorn/blob/fbf14f6e77f3cfc7a26b1004662d868a5a517a85/app/src/main/kotlin/com/arflix/tv/ui/screens/player/PlayerViewModel.kt#L19-L64) and [constructor](https://github.com/ReyesPascal/Pascal-The-Popcorn/blob/fbf14f6e77f3cfc7a26b1004662d868a5a517a85/app/src/main/kotlin/com/arflix/tv/ui/screens/player/PlayerViewModel.kt#L273-L286): profile manager, MediaRepository, StreamRepository, local watch/history, launcher continue-watching, skip-intro, telemetry, stream integration, recent sources and TMDB API. Profile-scoped preference keys remain even though the personal build presents a hidden single profile. “Profiles removed from UI” is not an independent-player architecture.

[Navigation](https://github.com/ReyesPascal/Pascal-The-Popcorn/blob/fbf14f6e77f3cfc7a26b1004662d868a5a517a85/app/src/main/kotlin/com/arflix/tv/navigation/AppNavigation.kt) carries media identity, season/episode and resume inputs into PlayerScreen. The view model also owns episode/air-date loading, show merge/anime identity, source collection and autoplay, preference persistence, subtitle fetching/matching, watched/progress updates and launcher integration. These are seams for Jetstream decisions, not reasons to retain all PTP repositories.

Candidates to replace/adapt with the Jetstream shell are catalog/search/details/navigation models, accounts/profile presentation, addon installation/configuration screens, home/library layout and branding. Useful watch progress, episode identity and local history behavior may survive behind new interfaces if the owner chooses; deleting them merely because they live in the app layer would lose resume/next-episode behavior.

Source discovery and fallback need special treatment. Existing PTP code recognizes Usenet Ultimate by addon ID/name, preserves that ordered subset, and separately applies device selection and max-three personal automatic attempts. KaijuFlow already owns backend discovery/health/ranking/preparation/candidate fallback. A Jetstream integration can change the client interface, but must consciously replace these identity/order assumptions and coordinate independent player/backend startup budgets. See [contract evidence](ptp-contract.md). No proposed prepare/status, capability handshake or shared telemetry endpoint should be described as already implemented.
