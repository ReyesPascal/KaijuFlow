# InfiniDysk integration contract

Research date: 2026-11-07. Planning evidence only; no service, host, benchmark or playback was run. “Source-observed” below means static inspection, not interoperability verification.

## Identity and version must be explicit

The intended project is strongly identifiable as **infinidysk/infinidysk**, the Usenet virtual filesystem exposing SABnzbd and WebDAV. The project itself distinguishes two supported generations: stable C#/.NET **1.x** on `v1`, and a Rust **2.x beta** on `main`. This resolves product identity, but does not choose which generation the owner wants KF to support. [Pinned current-generation README](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/README.md)

At inspection the GitHub latest stable release was **v1.7.1**, published 2026-11-03, commit `4a630deb6e599f3eadbe071a92417a93d74dc81f`. The newest prerelease was **v2.0.0-beta.6**, published 2026-11-06, commit `6363f4a4a3f1bcbc3308142b66ec3e7d7127f853`. These are the source pins in this report. [Stable release](https://github.com/infinidysk/infinidysk/releases/tag/v1.7.1), [beta release](https://github.com/infinidysk/infinidysk/releases/tag/v2.0.0-beta.6)

The beta uses `ghcr.io/infinidysk/infinidysk-next`; 1.x retains `ghcr.io/infinidysk/infinidysk`. Moving from 1.x to 2.x is a breaking migration, not an image-name-only upgrade. Indexed web results still return the old .NET README under a moving `main` URL; use pinned source and versioned docs. The README at the beta pin confirms Rust and the generation split. [README](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/README.md)

## Preparation and delivery surface

| Capability | Evidence and exact limits |
| --- | --- |
| NZB submission | **Source-observed, both generations.** SAB `/api?mode=addfile` accepts multipart `nzbFile` or file field `name`, optional `nzbname`, category and priority. Beta returns `status` and `nzo_ids` UUIDs; `addurl` uses URL parameter `name`. Beta can return a job ID even when URL retrieval/NZB validation failed: inspect history. Beta replies in JSON regardless of `output`. [beta dispatcher](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/sab.rs), [1.x request](https://github.com/infinidysk/infinidysk/blob/4a630deb6e599f3eadbe071a92417a93d74dc81f/backend/Api/SabControllers/AddFile/AddFileRequest.cs) |
| Readiness/status | **Source-observed.** Beta queue slots report `Queued`, `Paused` or `Downloading`, with ID, category, percentage and timeleft. History reports `Completed` or `Failed`, failure message and storage. A completed history row with a missing folder reports failed. 1.x has the same effective-folder status distinction and queue states. Acknowledged submission is not readiness. [beta SAB](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/sab.rs), [1.x history](https://github.com/infinidysk/infinidysk/blob/4a630deb6e599f3eadbe071a92417a93d74dc81f/backend/Api/SabControllers/GetHistory/GetHistoryController.cs), [1.x queue](https://github.com/infinidysk/infinidysk/blob/4a630deb6e599f3eadbe071a92417a93d74dc81f/backend/Api/SabControllers/GetQueue/GetQueueController.cs) |
| Progress | **Present but narrowly scoped.** Beta percentages/ETA derive from import snapshots, not bytes buffered for a player; absent ETA renders zero time. Queued jobs report zero. These fields do not establish an accurate playback-ready ETA. Do not manufacture a KF percentage or translate timeleft zero into ready. [beta SAB](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/sab.rs) |
| What completion means | **Documented, not a whole-file proof.** Beta import parses NZB/archive metadata, filters non-media, checks sampled articles plus media tail articles and video signatures. Provider errors/timeouts wait and retry; confirmed missing content or fake payload fails import. Only stored/uncompressed RAR/7z members stream; compressed archives are unsupported. The page says completed media can play start-to-end, but its described sampling is not exhaustive validation of every article. [beta import pipeline](https://www.infinidysk.com/v2/how-it-works/import-pipeline/) |
| File lookup/selection | **Source-observed.** WebDAV PROPFIND provides names, lengths, types and directories. Beta accepts depth 0/1 (missing treated as listing), rejects other depths with 403 finite-depth error. `/content/<category>/<job>/...` remains the useful tree; no generic “best episode file” selection API was established. Beta additionally exposes paged `GET /api/v1/files` with path/search/category/size filters and per-item details. KF can retain episode/sample/size selection. [WebDAV](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/webdav/src/lib.rs), [files](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/files.rs) |
| ID paths | **Source-observed portability constraint.** Beta `/.ids/a/b/c/d/e/<id>` is a sharded **file** ID tree, not an NZB-job folder. 1.x also shards IDs before resolving a file. Never assume returned SAB job ID is a playable file ID or that `/.ids/<job>` is supported. [beta VFS](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/vfs/src/lib.rs), [1.x IDs](https://github.com/infinidysk/infinidysk/blob/4a630deb6e599f3eadbe071a92417a93d74dc81f/backend/WebDav/DatabaseStoreIdsCollection.cs) |
| Media access | **Source-observed.** Beta GET/HEAD reads WebDAV files; `/view/<path>` uses the same media reader with query-key/token authorization. Beta `POST /api/v1/links` returns a path-specific signed `/view` URL and expiration (six hours). Paths/IDs/URL lifetime belong in adapter output, not a presumed permanent URL. [WebDAV](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/webdav/src/lib.rs), [links](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/files.rs) |
| Ranges/seeking | **Source-observed in both generations.** Beta handles one bounded, open-ended or suffix byte range; valid ranges return 206 with Content-Range/Length, unsatisfiable ranges 416 with total length. Malformed/non-byte/multiple ranges are ignored and return full content; multipart ranges are unsupported. HEAD returns full length and ignores Range. 1.x patched handler likewise resolves single ranges, suffix ranges and 416 and ignores malformed/multiple ranges. This establishes server behavior, not TV seek reliability. [beta range/get](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/webdav/src/lib.rs), [1.x handler](https://github.com/infinidysk/infinidysk/blob/4a630deb6e599f3eadbe071a92417a93d74dc81f/backend/WebDav/Base/GetAndHeadHandlerPatch.cs) |
| Probe limits | **Source-observed.** Beta reads the first chunk before starting the response and can return 503/Retry-After on read failure. Its source explicitly says missing articles are zero-filled and reported to health. A successful first-byte range probe therefore is not proof of complete healthy media. [beta get](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/webdav/src/lib.rs) |
| Cancel preparation | **Material generation difference.** 1.x queue removal invokes QueueRemovalService and can answer `status:false` with items “still stopping”; caller must verify/retry. Beta SAB `queue&name=delete&value=<id>` removes the DB job; a source comment explicitly says active import cancellation is not implemented and a removed active import drops its result when it finishes. This is not guaranteed immediate NNTP/work cancellation. [1.x removal](https://github.com/infinidysk/infinidysk/blob/4a630deb6e599f3eadbe071a92417a93d74dc81f/backend/Api/SabControllers/RemoveFromQueue/RemoveFromQueueController.cs), [beta delete_queue](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/sab.rs) |
| Delete completed media | **Do not conflate queue/history deletion with media removal.** Beta content is read-only through WebDAV; DELETE supports queued NZBs, and deleting completed-symlink entries only temporarily hides links. Authenticated `DELETE /api/v1/files/{id}` removes eligible item/subtree; `forget_history` is separate and protected roots/categories have guards. A removal-preview endpoint exists. 1.x has `api/delete-webdav-item`, subject to read-only/protected-root/in-progress guards and optional expected item identity. Exact ordinary 1.x WebDAV DELETE coverage was not audited here. [beta WebDAV](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/webdav/src/lib.rs), [beta link hiding](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/vfs/src/lib.rs), [beta deletion](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/files.rs), [1.x deletion](https://github.com/infinidysk/infinidysk/blob/4a630deb6e599f3eadbe071a92417a93d74dc81f/backend/Api/Controllers/DeleteWebdavItem/DeleteWebdavItemController.cs) |
| Authentication | **Separate credentials/surfaces.** Beta SAB takes `X-Api-Key` or `apikey`, matched against `sab.api_key`; `mode=version` is unauthenticated and advertises SAB compatibility version 4.5.1, not InfiniDysk's build version. Admin API uses session cookie or X-Api-Key/Bearer matching `auth.api_key` (subject to configured auth exemptions). WebDAV uses Basic auth; `/view` accepts download key, signed token or path-scoped STRM key. 1.x custom/SAB APIs share a validator accepting configured API key or frontend/backend environment key. Do not interchange these secrets or expose them in logs. [beta SAB](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/sab.rs), [beta admin auth](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/auth.rs), [beta WebDAV](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/webdav/src/lib.rs), [1.x validator](https://github.com/infinidysk/infinidysk/blob/4a630deb6e599f3eadbe071a92417a93d74dc81f/backend/Auth/ApiKeyValidator.cs) |

## Fit against KaijuFlow's NzbDAV responsibility map

The existing KF map describes: D03 submit XML; D04 poll/cancel; D05 library/file selection; D06 prepare and initial-byte probe; D08–10 deliver/proxy/range/reconnect; D11–13 cache/invalidation/source fallback; D14 deletion; D15 auth. It deliberately distinguishes static evidence and tiny fake-service tests from production behavior. Its historical links use the original import pin; current source and AUDIT take precedence over historical defect status. This report compares responsibilities, not a fresh audit of KF's implementation. [KF reference at agreed checkpoint](https://github.com/ReyesPascal/KaijuFlow/blob/6565c1a7c810e2cb2bf7d4e1239e545adbd4236e/docs/kaijuflow/references/nzbdav/ARCHITECTURE.md)

**Inference from the interfaces:** a selected-NZB adapter can submit, poll, enumerate files and expose authenticated range-readable media while KF retains discovery, indexers, health eligibility, ranking and release fallback. No InfiniDysk-managed search is required for that path. Its own import integrity checks still exist; retaining KF health checks does not imply those downstream checks disappear. The existing KF byte probe remains useful only as an initial-servability signal, especially given beta zero-fill behavior. [SAB](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/infinidysk/src/sab.rs), [WebDAV](https://github.com/infinidysk/infinidysk/blob/6363f4a4a3f1bcbc3308142b66ec3e7d7127f853/crates/webdav/src/lib.rs), [KF reference](https://github.com/ReyesPascal/KaijuFlow/blob/6565c1a7c810e2cb2bf7d4e1239e545adbd4236e/docs/kaijuflow/references/nzbdav/ARCHITECTURE.md)

Specific constraints for a later specification: target generation/capability detection; separate job and file IDs; readiness versus buffering/health; optional progress; cancellation acknowledgment versus stopped work; deletion mechanism and cache invalidation; URL expiry and credential custody. These are decision inputs, not settled architecture.

The generations are not feature-identical: first-party comparison lists search/addon/Stremio as 1.x-only for now, PAR2 repair absent in beta, and Watchtower/Preflight/Warden not planned for 2.x. Therefore a 1.x search-profile `/play` workflow must not be assumed to exist in beta or substituted for KF orchestration. [Version comparison](https://www.infinidysk.com/v2/whats-new/)

## Remaining uncertainty and evidence limits

The owner must identify the intended stable/beta support target; no deployed instance/version was inspected. Exact KF compatibility with each pinned release, archive/episode layouts, authentication through the chosen front door, cancellation races, long-lived/expired URLs, stale-library behavior, real range seeking and playback recovery require later authorized contract tests. No comparative performance conclusion, replacement recommendation or default promotion follows from docs, language, maintenance status or upstream benchmark claims. No cross-backend fallback or human design choice is settled here.
